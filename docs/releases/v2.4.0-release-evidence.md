## 3. P0 & P1 Hardening Actions Completed

### 3.1 Stripe Webhook Durability & State Correctness (P0-A, P0-B, P0-C)
- **Problem Fixed:** Webhook handler previously relied on in-memory `Map` that lost queued events on process restart; duplicate deliveries could silently acknowledge failed events; and partial DB failures were caught without failing closed.
- **Implementation:**
  - In `src/lib/billing/stripeWebhook.ts`, `processQueuedStripeEvent` now rehydrates event payload and status from `stripe_webhook_events` table in PostgreSQL when not present in memory.
  - On duplicate delivery, `src/app/api/billing/webhook/route.ts` inspects persisted event status: returns 200 idempotent response only if already `processed`; if `pending` or `failed`, triggers re-processing retry.
  - Subscription event validation enforces payment status checks on `checkout.session.completed` before activating entitlements.
  - Unknown/missing plan tiers fail closed instead of defaulting to `professional`.
  - Database persistence writes fail closed in production (throws on error rather than swallowing).
- **Verified by:** `tests/commercial-stripe-checkout-and-licensing.test.ts` and `tests/stripe-lifecycle.test.ts`.

### 3.2 Checkout Redirect URLs & Idempotency (P0-D)
- **Problem Fixed:** Client-supplied redirect destinations were unvalidated; checkout attempt idempotency could continue with unsaved attempt ID.
- **Implementation:**
  - In `src/lib/billing/checkoutService.ts`, `validateRedirectUrl` validates protocol, host, port, and enforces HTTPS in production against configured application origin.
  - Idempotency conflict resolution queries and returns the existing durable attempt rather than proceeding with an unsaved in-memory ID.

### 3.3 Database TLS Certificate Validation (P1-G)
- **Problem Fixed:** `rejectUnauthorized: false` was hard-coded for non-local PostgreSQL connections, bypassing certificate validation.
- **Implementation:**
  - In `src/lib/db/index.ts`, TLS certificate validation is enabled by default in production (`rejectUnauthorized: true`), supporting custom CA certificate via `DATABASE_SSL_CA` and explicit overrides via `DATABASE_SSL_REJECT_UNAUTHORIZED`.

### 3.4 Truthful Status & Scan Telemetry (P1-H)
- **Problem Fixed:** `/api/status` reported unprobed services as operational and returned a synthetic always-resolved incident. `/api/scans` returned hard-coded counts (`patchedHosts: 14`) and fake recent scans.
- **Implementation:**
  - In `src/lib/status/serviceStatus.ts`, AI status reports `degraded` when falling back to heuristic rule-based analysis; Stripe configuration is probed; synthetic `inc-shielddesk-live` incident is eliminated in production; and application version is dynamically read from environment.
  - In `src/app/api/status/route.ts`, public 503 error responses redact raw exception details in production.
  - In `src/app/api/scans/route.ts`, removed hard-coded `patchedHosts: 14`, `pendingPatches: 2` and static scan examples. Replaced with real persisted tenant scan data (`lastScan` and `cachedGitleaks`). `rotate_key` and `apply_patch` fail closed against simulated execution in production.

### 3.5 SIEM Ingestion Security (P1-10)
- **Problem Fixed:** Ingestion HMAC branch derived tenant ID from request header with a shared secret; DB writes were swallowed in fallback mode.
- **Implementation:**
  - In `src/app/api/ingest/siem/route.ts`, constant-time API key verification using `crypto.timingSafeEqual` against configured ingest keys is enforced. Database write failures throw and return 500 error in production.

### 3.6 Endpoint Agent Deploy Scripts (P1-11)
- **Problem Fixed:** `deploy-agent.sh` and `deploy-agent.ps1` defaulted to `http://localhost:3000` and `acme-tenant`, and printed raw enrollment tokens to stdout.
- **Implementation:**
  - Both scripts now require explicit control-plane URL and enrollment token/tenant; require HTTPS in production; reject `localhost:3000` without explicit `-Dev` / `--dev` flag; and redact enrollment tokens from console logs.

### 3.7 Governance, Licensing & Disclosure (P1-L)
- **Implementation:**
  - Added root `LICENSE` file establishing clear Commercial & Community Evaluation terms.
  - Added root `SECURITY.md` establishing vulnerability disclosure policy, response SLAs (24h triage, 72h assessment, 7d critical patch), and supported versions.
